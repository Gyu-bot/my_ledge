# 02. 새 정보 구조 (IA) & 페이지 구성

> 입력: [01-functional-inventory.md](01-functional-inventory.md)의 정보/역할 + 횡단 관찰 6가지.
> 원칙: 기능은 전부 보존하되, 사용자의 **질문** 단위로 페이지를 다시 자른다.

## 1. 설계 원칙

1. **질문 중심 IA** — 메뉴는 데이터 종류가 아니라 사용자의 질문에 대응한다.
   - "지금 내 돈 상태는?" → 홈
   - "어디에 쓰고 있나?" → 지출
   - "자산과 빚은 어떻게 변하나?" → 자산·부채
   - "뭘 신경 써야 하나?" → 신호
   - "데이터를 정리·보강하려면?" → 데이터 스튜디오
2. **읽기와 운영의 명확한 분리, 그러나 한 번의 점프** — 분석 화면은 조회 전용을 유지한다. 대신 모든 분석 화면의 "데이터가 부족하다/미분류다" 지점에서 데이터 스튜디오의 정확한 작업 지점으로 딥링크한다.
3. **도메인 단위 운영** — 운영 화면은 작업 종류(연결/규칙/설정)가 아니라 도메인(거래/대출/할부/자산)으로 묶는다. 대출 관련 작업 3곳 분산 문제를 이걸로 푼다.
4. **인박스 패턴** — 분류 품질 큐 + dry-run 승인 대기 + 미연결 후보를 하나의 "처리해야 할 일" 피드로 통합하고, 데이터 스튜디오의 기본 진입점으로 둔다.
5. **신뢰 수준의 단일 언어** — 관측(observed) / 수동(manual) / 규칙(auto) / 추정(estimated)의 4단계 출처 체계를 전역 배지·팝오버 패턴으로 통일한다. (→ 04 디자인 시스템의 `Provenance` 컴포넌트)
6. **기간 컨트롤의 계층화** — 페이지 헤더에 전역 기간(페이지 범위 상태), 섹션에는 예외적인 로컬 컨트롤만. 로컬 컨트롤은 "전역과 다름" 표시를 단다.

## 2. 최상위 내비게이션 (5 + 1)

```
홈            /                      이번 달 재무 상태 요약 + 해야 할 일
지출          /spending              지출의 추이·구성·고정비·거래처·달력
자산·부채      /net-worth             스냅샷 기반 자산/부채/대출/할부 잔여
신호          /signals               이상지출·반복결제·재량속도·구매게이트·MoM
데이터        /data/*                 운영 통합 (서브 내비 8)
─────
(보조) 데이터 사전  /data/reference   canonical view / 스키마 레퍼런스
```

데이터 스튜디오 서브 내비:

```
/data/inbox          인박스        분류 품질 큐 + dry-run 승인 + 미연결 후보 통합 피드
/data/transactions   거래          작업대 (테이블·인라인 편집·일괄 작업)
/data/loans          대출          계좌 메타 + 거래 연결 + 상환 메타 + 매칭 규칙
/data/installments   할부          계획 + 거래 연결 + 월별 예측
/data/assets         자산 메타      유동성 등급 / 현금성 여부
/data/rules          규칙          카테고리·정규화·반복결제 규칙 + 자동 적용 토글
/data/settings       설정          분석 파라미터 + 재무 목표 (settings/analytics)
/data/import         가져오기       업로드 + 이력 + 초기화(danger)
/data/reference      데이터 사전     canonical 수치 검증 + view/스키마 레퍼런스
```

### 왜 이렇게 잘랐나

| 결정 | 근거 (인벤토리 관찰) |
|---|---|
| `개요` → `홈`으로 확장, **실질 가용액을 1번 KPI로 승격** | true spendable은 이 제품의 가장 해석된 숫자인데 캐노니컬 뷰 구석에 있었다 (관찰 5) |
| `인사이트` → `신호` | "인사이트"는 읽을거리 느낌. 실제 내용은 행동 트리거(이상치, 후보, 위험도)다 |
| 운영 7메뉴 → 데이터 스튜디오 1 + 서브 9 | 평면 나열 해소 (관찰 1), 최상위 인지 부하 11 → 5 |
| `/data/settings` 신설 | backend `settings/analytics` 확장(분석 파라미터 + financial_targets)으로 저장형 설정 표면이 생김 — [07 동기화](07-backend-sync-20260611.md) |
| 대출 작업 통합 `/data/loans` | 계좌 메타·거래 연결(대출 연결) + 상환 메타(자산 설정) + 매칭 규칙(자동분류)이 3곳 분산 (관찰 2) |
| 인박스 신설 | 분류 품질 루프의 단일 입구 (관찰 5). 신규 화면이지만 **새 API 불요** — 기존 큐·dry-run·미연결 쿼리 조합 |
| 캐노니컬 뷰 해체 | KPI·실질 가용액 → 홈, 월별 현금흐름 → 홈/지출, 검증 테이블·스키마 → 데이터 사전 |

## 4. 페이지별 역할 정의

### 4.1 홈 `/`
- **질문:** "이번 달, 나는 얼마나 쓸 수 있고 무엇을 처리해야 하나?"
- 구성: ① 히어로 KPI(실질 가용액 — 예상/관측 구분 포함) ② 보조 KPI(순자산/수입/지출/저축률) ③ 현금흐름 12개월 ④ 주의 신호(신호 페이지 요약) ⑤ 해야 할 일(인박스 요약: 미분류 N, 승인 대기 N, 미연결 N) ⑥ 최근 거래
- 모든 카드는 해당 상세 페이지로 딥링크.

### 4.2 지출 `/spending`
- **질문:** "어디에, 어떤 성격의 돈을 쓰고 있나? (그리고 수입은 어떻게 들어오나?)"
- 페이지 헤더에 전역 기간 컨트롤(프리셋 3/6/12개월 + 커스텀 월 범위 + 수입 포함 토글).
- 렌즈 탭: `추이`(스택 바+카테고리 MoM) / `구성`(대분류→소분류 드릴) / `고정비`(고정·변동, 필수·재량, 미분류 게이지+인박스 딥링크) / `거래처`(treemap + Top N) / `달력` / `수입`(월별 수입 카테고리 구성 — backend `vw_income_monthly_by_category` 공식화에 대응, 1차 데이터는 `by-category(type=수입)`).
- 거래 내역은 모든 렌즈 하단 공통 패널(현재 렌즈의 선택을 필터로 반영 — 예: 구성에서 "식비" 클릭 → 거래 내역이 식비로 필터).

### 4.3 자산·부채 `/net-worth`
- **질문:** "자산·부채 스냅샷은 어떻게 변하고 있고, 빚 상환 부담은 얼마인가?"
- 구성: ① KPI ② 순자산 추이+구성(음수 자산 제외분은 Provenance) + 신용점수 카드(KCB 점수+이력 스파크라인, 나이·성별 메타 — `GET /profile`) ③ 유동성 보드(현금성/비상금/월부채 + **비상금 목표 대비 진행률 게이지**(`emergency_fund_target_months`·`target_progress_ratio`) + 자산별 유동성 목록, 편집은 `/data/assets` 링크) ④ 대출 보드(대출 카드: 잔액·금리·월상환·**월 이자 추정**(`estimated_monthly_interest`, 단리 추정 ⓘ)·상환방식·원금 대비 진행률 — 정렬 힌트로 부채 전략(avalanche=고금리순/snowball=잔액순) 반영) ⑤ **투자 보드**(종목별 평가액·수익률·비중 `pct_of_investment_total` bar) ⑥ **보험 보드**(계약 목록: 보험사/상품/상태/총납입/만기 + 월 보험료 추정 ⓘ assumptions — evidence만 표시, 적정성 판단 문구 없음) ⑦ 할부 잔여 요약(Remaining/Missed → `/data/installments` 링크)
- 스냅샷 비교 메타(이전 대비·경과일·stale)는 페이지 헤더 고정 + 비교 모드 선택(`latest vs previous` / `last_closed_month_vs_previous_closed_month`).

### 4.4 신호 `/signals`
- **질문:** "전과 다른 것, 위험한 것, 검토할 것은?"
- 모든 항목을 **신호 카드** 단일 패턴으로 통일: 제목 / 심각도 / 근거(기준선·증감·confidence·assumptions를 Provenance 팝오버로) / 액션(관련 화면 딥링크).
- 섹션: ① 신호 피드(핵심 인사이트+이상 지출+구매 게이트 통합, 심각도 정렬) ② 재량 지출 속도 게이지 ③ 반복 결제 현황(조회 전용, "분류 바꾸기 → 데이터") ④ 비교 도구(카테고리 MoM, 거래처 Top)
- 구매 게이트 카드는 **서버 영속 리뷰 워크플로**: 검토함/무시/스누즈(N일, 기본 14일)/메모 → `PATCH purchase-gate-candidates/{key}/review`. 스누즈된 카드는 `cooldown_until`까지 피드에서 숨김.
- 기준 모드(직전 마감월/부분 기간)는 페이지 헤더에서 1회 선택 — 이상 지출·주의 신호가 공유. "마감월" 판정은 canonical의 `is_complete_month` 플래그를 단일 기준으로 사용.
- 저축률 목표 등 임계값은 하드코딩하지 않고 `settings/analytics`의 `financial_targets`를 읽는다 (편집은 `/data/settings`).

### 4.5 데이터 스튜디오 `/data/*`
- **질문:** "분석을 믿을 수 있게 데이터를 정리하자."
- 공통 헤더: 분류 커버리지 게이지(cost_kind/필수·재량/반복/대출 연결 커버리지) — 인박스 처리가 줄어드는 걸 보여주는 진행 표시.
- **인박스:** 우선순위 사유별 그룹(미분류 고정비 후보 / 반복 후보 / 대출 연결 후보 / dry-run 승인). 카드에서 바로 처리(인라인 분류·승인) 또는 해당 도메인 화면으로 점프.
- **거래:** 기존 작업대 + 뷰 토글 `행 보기 ↔ 그룹 보기(거래처 단위)`. 그룹 보기가 기존 "반복 결제 분류" 화면을 흡수 — 같은 bulk-update를 거래처 그룹 단위로 수행.
- **대출:** 탭 `계좌`(메타+상환 메타 통합 카드) / `거래 연결`(후보 테이블+일괄 연결) / `규칙`(대출 매칭).
- **할부:** 탭 `계획` / `거래 연결` / `예측`.
- **자산 메타:** 유동성 등급/현금성 편집.
- **규칙:** 탭 `카테고리`(고정·변동/필수·재량) / `거래처 정규화` / `반복결제` + 자동 적용 토글 패널. 각 규칙에 "일괄 적용" + 적용 결과 알림.
- **설정:** `settings/analytics` 편집 — `재무 목표`(비상금 목표 개월, 저축률 목표, 부채 전략 avalanche/snowball)와 `분석 파라미터`(이상지출 threshold/baseline 개월, 재량 속도, 구매 게이트, dry-run, 월상환 추정 lookback 등 섹션별) 두 그룹. default/saved/effective 3값 구분 표시.
- **가져오기:** 업로드(스냅샷 기준일 필수, 결과는 거래 + 자산/보험/투자/대출 스냅샷 4종 카운트) / 이력 / 관측 데이터 범위(`data_coverage`) / Danger Zone(거래만 vs 거래+스냅샷 — 스냅샷 범위에 보험 포함 명시).
- **데이터 사전:** canonical KPI·월별 테이블(검증용 원본 수치, `is_complete_month` 플래그 표시) + view reference + 스키마 + import parity 검증 결과(현금흐름 벤치마크 경고) 자리.
