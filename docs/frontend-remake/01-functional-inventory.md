# 01. 현재 프론트엔드 기능 인벤토리 (정보 + 역할)

> 기준: `frontend/src` 코드 (2026-06-10, `main` e938435).
> 와이어프레임·레이아웃·스타일은 의도적으로 배제하고, **무엇을 보여주는가 / 사용자가 무엇을 할 수 있는가**만 기록한다.

## 0. 전역 (앱 셸 공통)

### 보여주는 정보
- 내비게이션: 3개 섹션 — 개요(1) / 분석(3: 지출 분석, 자산 현황, 인사이트) / 운영(7: 거래 작업대, 대출 연결, 할부 관리, 자산 설정, 자동분류, 캐노니컬 뷰, 반복 결제 분류)
- 페이지 타이틀 + breadcrumb
- 페이지별 메타 배지 (페이지가 topbar에 주입): 기준일, 조회 기간, N/M건, 규칙 수, 핵심 인사이트 수, canonical 개월 수 등
- read-only 모드 경고 (API 키 부재 시 페이지마다 배너)
- 작업 결과 알림 배너 (성공/실패 + 설명, 일부는 undo 액션 포함)
- 로딩 / 에러(재시도 버튼) / 빈 상태 (모든 데이터 섹션 공통)

### 역할
- 데스크톱 사이드바 + 모바일 드로어 전환
- read-only 여부에 따라 모든 쓰기 컨트롤 비활성화

## 4. 인사이트 `/analysis/insights` — 조회 전용

### 보여주는 정보
| 정보 | 세부 |
|---|---|
| KPI 3종 | 저축률 / 수입 변동성 등급 / 이상 지출 카테고리 수 |
| 핵심 인사이트 | 클라이언트 룰 조합 (저축률 달성/미달, 이상 지출 감지, 반복 결제 감지, 수입 안정성) — 심각도 배지(양호/주의/확인 필요) |
| 재량 지출 속도 | velocity ratio(배수), risk level(낮음/관찰/주의/높음), 현재 재량 지출 vs 진행률 기준선, 월 진행률·분류 커버리지·confidence, 사유 텍스트 |
| 구매 게이트 후보 | pending 후보: 거래처/날짜/금액, risk 배지, 후보 타입(큰 일회성/신규 거래처/거래처 급증/재량 급증), 시그널 key-value, 사유 |
| 반복 결제 | 테이블: 거래처/저장된 분류(할부·매월·미분류 건수 분포)/주기/평균금액/횟수 + 진단 기준(assumptions) 토글, 페이지네이션 |
| 이상 지출 | 테이블: 카테고리/이번 달/기준선/증감% + 기준 모드 + assumptions 토글, 페이지네이션 |
| 거래처 소비 Top 5 | 기간 선택(1/3/6/12개월): 순위/거래처/건수/평균/합계 |
| 카테고리 전월 대비 | 기준월 선택, MoM 증감 bar 목록 |

### 역할
- 이상 지출 기준 모드 전환 (직전 마감월 / 부분 기간 — 오늘 cutoff 비교 설명 포함)
- 진단 기준(assumptions) 펼치기
- 반복 결제/이상 지출 페이지네이션, 거래처 기간·MoM 기준월 선택
- **수정 없음** — 반복 분류 변경은 운영 화면에서만 (역할 분리 원칙)

## 5. 거래 작업대 `/operations/workbench`

### 보여주는 정보
- 거래 테이블 (40행/페이지): 선택 체크박스, 날짜, **원본 설명(read-only)**, 분석용 거래처, 대분류/소분류(effective), 고정/변동, 필수/재량(spend_necessity), 반복분류, 메모, 상태 배지(원본/수정됨/삭제됨 — 삭제는 취소선+흐림), 금액, 동작
- 일괄 작업 preview: 건수, 기간(시작~끝), 지출 합계, 대표 거래처 목록
- 업로드 결과: 신규/스킵 건수 + 파일명
- 업로드 이력 10건: 파일명/상태(success·partial·failed)/신규/스킵/기준일/업로드 시각

### 역할
| 역할 | 세부 |
|---|---|
| 필터 | 검색(거래처·원본 설명·메모), 거래 유형, 입력 출처(import/manual), 대분류, 결제수단, 고정/변동, 고정비 필수 여부, 필수/재량, 반복분류, 날짜 범위, 삭제 포함, 수정만 — draft → 적용 버튼 방식 |
| 행 인라인 편집 | 거래처, 대분류→소분류(종속 드롭다운), 고정/변동, 필수/재량, 반복분류, 메모. 편집 중 다른 행 선택 잠금 |
| 행 삭제/복원 | 소프트 삭제, 삭제 행은 복원만 가능 |
| 일괄 편집 | 페이지 전체 선택(indeterminate 지원), 선택 행에 거래처/대분류/소분류/고정·변동/필수·재량/메모 일괄 적용 |
| 일괄 삭제/복원 | preview(건수·기간·합계·대표 거래처) 확인 후 실행, 실행 직후 "방금 삭제한 항목 복원" undo |
| 업로드 | xlsx 드래그&드롭(최대 20MB), **스냅샷 기준일 필수 입력**, 실행 |
| 데이터 초기화 | 범위 선택(거래만 / 거래+스냅샷), 확인 문구 타이핑 후 실행. 업로드 이력은 보존 안내 |

## 6. 대출 연결 `/operations/loan-mapping`

### 보여주는 정보
- 대출 계좌 목록 (lender+product 기준 dedupe): 최신 스냅샷일/신규일/만기일/잔액/금리 메타
- 대출 상환 후보 거래 테이블: 날짜/원본 설명/분석용 거래처/대분류·소분류/연결 대출(표시명) 또는 미연결 배지/상환 성격/금액, 연결 메모

### 역할
- 필터: 검색(거래처·설명·메모·계좌), 연결 상태(전체/연결/미연결), 대출 계좌, 상환 성격, 날짜 범위
- 계좌 메타 편집: 표시명(display_name_user), 대출 성격(loan_kind: 미지정/마이너스 통장/원리금 균등/원금 균등/일시 상환/기타) 저장 — 거래 연결과 분리
- 거래 선택(페이지 전체 선택 지원) → 일괄 연결: 대출 계좌 + 상환 성격(원리금/이자/원금/미정) + 메모

- 일괄 연결: 계획 + 시작 회차(연속 회차 자동 배정) + 메모

- 예측 컨트롤: 기준일(as_of_date), 개월 수(1~24)
- URL prefill 수신: 반복 결제 분류에서 거래처/월 금액/검색·미연결 필터를 들고 진입

### 보여주는 정보
- 규칙 목록 4종 테이블: ① 카테고리→고정·변동/필수·재량 ② 거래처 정규화(포함 패턴→정규 거래처) ③ 카테고리→반복결제 성격 ④ 대출 매칭(기준 필드/매칭 값/대출 계좌/상환 성격)
- 총 규칙 수 (메타 배지)

### 역할
- 업로드 후 자동 적용 토글 3종 (고정비 규칙 / 대출 거래처 규칙 / 반복결제 규칙)
- 규칙 등록(upsert): 각 폼 — 대분류·소분류(종속), 비용 성격, 필수/재량 / 포함 패턴·정규 거래처 / 반복 성격 / 매칭 기준(분석용 거래처·원본 설명)·매칭 값·대출 계좌·상환 성격·메모
- 규칙별 "일괄 적용" (기존 데이터, manual 값은 덮지 않음 — 고정비 규칙 적용 시 작성 중인 폼은 자동 저장 후 적용)

## 10. 반복 결제 분류 `/operations/recurring-classification`

### 보여주는 정보
- dry-run 승인 후보: 거래처별 — 제안 분류, confidence %, 사유, 카테고리 힌트, 매칭 거래 칩(날짜·금액), 적용 범위 옵션 목록
- 반복 결제 후보 테이블 (20행/페이지): 분석용 거래처/카테고리/주기/평균금액/횟수/현재 결과(저장 분류 + 할부·매월·반복아님·미분류 분포 요약)

### 역할
- dry-run 적용 범위 선택(all_matching 우선 정렬) → 승인 적용
- 그룹별 분류 변경 드롭다운(미분류/할부/매월 반복/반복 아님) → **즉시 저장** (그룹의 transaction_ids 전체 bulk-update, 실패 시 롤백)
- 그룹 다중 선택(페이지 전체 선택) → 같은 분류 일괄 적용
- 할부로 분류된(또는 제안된) 그룹 → 할부 관리로 거래처/평균금액 prefill 딥링크

## 12. 횡단 관찰 (리메이크 설계 입력)

1. **두 가지 모드가 섞여 있다** — "읽고 해석"(개요/지출/자산/인사이트/캐노니컬)과 "데이터를 만지는 운영"(작업대/연결/할부/설정/규칙/반복분류). 운영 7개 메뉴가 평면 나열되어 있다.
2. **대출 관련 작업이 3곳에 분산** — 계좌 메타·거래 연결(대출 연결), 상환 메타(자산 설정), 매칭 규칙(자동분류).
3. **추정치 표기가 화면마다 다르다** — `예상` 배지, `*_est`, confidence %, assumptions 토글, 출처 라벨이 제각각.
4. **기간 컨트롤이 섹션마다 제각각** — 추이 전용 범위, 상세 필터 범위, 달력 월, MoM 기준월, merchant 개월 수.
5. **분류 품질 루프가 핵심인데 입구가 숨어 있다** — 미분류/미연결이 모든 분석 품질을 좌우하지만, 작업 큐(`vw_unclassified_work_queue`)는 캐노니컬 뷰 구석에 있다.
6. **같은 데이터의 신뢰 수준이 다층적** — 원본(import) → 사용자 수정(manual) → 규칙(auto) → 추정(estimated). 이 출처 체계가 UI 언어로 통일되어 있지 않다.
