## 설계 전제

- **기능 보존:** 01 인벤토리에 있는 모든 정보/역할은 새 설계 어딘가에 자리가 있어야 한다. 기능 삭제는 이 초안의 범위가 아니다 (위치 이동·통합은 적극적으로 한다).
- **백엔드 무변경:** 기존 API/canonical view 계약(`docs/backend-api-ssot.md`)을 그대로 소비한다. 새 endpoint 요구가 생기면 명시적으로 "백엔드 요청" 박스로 표기한다.
- **단일 사용자, 셀프호스팅:** 멀티테넌시/온보딩/마케팅 화면은 설계하지 않는다.
- **read-only 모드:** API 키가 없으면 모든 쓰기 동작이 비활성화되는 동작은 전역 개념으로 유지한다.

## 이 초안이 결정하지 않는 것

- 구현 순서/마이그레이션 전략 (별도 plan에서)
- shadcn/ui 등 구체 라이브러리 선정 (디자인 토큰은 라이브러리 중립으로 기술)
- 백엔드 스키마 변경
