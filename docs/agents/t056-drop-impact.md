# T056 컬럼 삭제 영향 분석 (PR B)

2026-11-17 · PR A 위에 쌓는 별도 승인 단계. 이 분석을 먼저 PR 본문에 기록한 뒤 삭제 이행을 구현한다. 실제 서버나 개인 자료를 조회하지 않는다.

## 가져오기 계약

- 파서의 `TransactionRow`, 업로드 preview/apply의 원본·선택·건수 HTTP 구조에는 이전 분류 컬럼이 없다. 이전 값 복사는 PR A에서 제거했다. 새 거래는 미분류 상태이며 자동 분류·추천을 하지 않는다.
- 교체 재가져오기는 `move_nature_override`로 거래 지정과 필요한 명시적 정기 지급 소속을 이동한다. 대출·할부 연결과 카테고리 사용자 지정·메모·원본 행 보존은 유지한다. 새 축의 세 표는 기존 전체 장부 스냅샷 범위에 이미 들어 있다.
- 검토 `finance_tables/state_digest`는 ORM 표의 모든 행·컬럼을 포함한다. 되돌리기 `fingerprint/snapshot`은 실제 PostgreSQL 전체 행의 JSON 표현을 포함한다. 따라서 거래 컬럼을 삭제하면 기존 준비 검토와 되돌리기 지문의 의미가 달라진다. 업로드 로그는 이전 분류를 독립 필드로 저장하지 않으며 기존 로그/원본 증거는 유지한다.
- 기존 준비 검토는 다시 준비해야 한다. 이행에서 prepared → stale로 표시하고 payload 상태도 맞춘다. 기존 ready 되돌리기 지점은 expired로 표시하되 스냅샷과 지문을 보관한다. 예전 지점을 강제 복원하는 `accept_changes`도 유효하지 않다. 새 상태를 새 HTTP 필드나 상태코드로 만들지 않고 기존 stale/expired/409 계약을 사용한다. 이전 T056 구조 변경 때처럼 기존 승인·되돌리기 지점을 재사용할 수 없다.
- 이행 이후 새 검토 준비·적용·되돌리기는 새 구조로 작동해야 하며 합성 PostgreSQL 통합 테스트로 검증한다. downgrade는 이전 승인이나 되돌리기 지점을 다시 유효하게 만들지 않는다.

## 외부 구조 의존 도구

저장소 밖의 에이전트 되돌리기 도우미와 읽기 전용 SQL 클라이언트는 이번 작업에서 조회·수정하지 않는다. 검토자가 아래 이름으로 호환성을 점검한다. 표 자체는 삭제하지 않는다.

- PR B에서 사라지는 컬럼: `transactions.cost_kind`, `transactions.fixed_cost_necessity`, `transactions.spend_necessity`, `transactions.recurring_payment_kind`, `transactions.cost_classification_source`.
- PR B에서 추가로 사라지는 뷰는 없다. PR A에서 사라지는 뷰·필드는 [전체 목록](t056-classification-retirement.md#가역적-뷰-이행-20261117_0041)을 따른다. 특히 `vw_recurring_merchant_monthly` 전체와 세 거래/흐름 뷰의 이전 분류 투영, 현금흐름/고정비/가처분/작업 큐의 이전 분류 파생 필드다.
- 현재 저장소 이행 정의에는 이 다섯 거래 컬럼을 쓰는 인덱스나 명시적 제약이 없다. 실제 합성 DB 카탈로그도 확인한다. DROP COLUMN 자체의 PostgreSQL 처리가 해당 컬럼의 로컬 인덱스/제약을 함께 제거하며 CASCADE로 외부 의존성을 우회하지 않는다. 예기치 않은 외부 뷰 의존성이 있으면 이행이 실패해야 한다.
- `category_classification_rules`, `recurring_category_rules`, `auto_classification_settings`의 과거 설정과 정의는 동결 기록으로 남는다. 적용 경로는 PR A에서 제거했다. 카테고리 체계나 새 축 표·컬럼 이름은 바꾸지 않는다.

## 사람이 입력한 값의 유실 방지

삭제 전 검증은 금액·거래처·카테고리 이름을 출력하지 않는 건수 전용 SQL이어야 한다. 지출의 이전 값은 승인된 T056 대응표와 비교하고, 명시적인 새 사용자 지정은 이후 결정으로 인정한다. 기존 고정/변동 값과 주기·금액 성격·조정 가능성·충돌/할부 확인 표식을 대조한다. 삭제·병합·대체 행도 검사하며 관계를 따라가는 분류 보존을 확인한다. 알 수 없는 이전 값이나 새 축에만으로 표현되지 않은 사람 입력은 하나라도 있으면 거절한다.

같은 SQL을 문서와 이행에 동결해 두고 모든 건수가 0일 때만 삭제한다. 검사 실패는 행 식별자나 금융값 없이 원인별 건수와 분류 보존을 먼저 해결하라는 메시지를 낸다. 이행은 자동 분류하거나 값을 추천하지 않으며 자료를 억지로 맞추지 않는다.

## 복구 한계와 병합 판단

이행은 `20261117_0041` 다음의 `20261117_0042`로 계획한다. downgrade는 다섯 nullable 컬럼만 재생성하며 예전 값은 복구하지 않는다. 삭제는 데이터 손실이 있고 컬럼 재생성만으로 이전 데이터나 이전 승인 상태를 복원할 수 없다. 별도 백업 복원·배포는 이 작업 범위가 아니다.

합성 장부의 0건 검사·실패 차단·새 축/흐름표/큐브 및 `/read/*` 동일성·가져오기/되돌리기 통합 검증이 통과하고, 검토자가 외부 구조 의존 도구와 실제 대상 DB의 0건 결과를 확인한 뒤 병합을 권고한다. 0건 조건이 충족되지 않으면 병합/이행하지 않는다. 라이브 분류 상태가 확인되었다고 주장하지 않는다.
